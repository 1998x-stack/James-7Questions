# DMAIC：把实验能力变为可持续改进系统：Booking.com：把实验文化变成竞争能力

> 研究时段：2017—2019｜公司：Booking.com / 缤客｜行业：在线旅游 / 住宿预订平台 / 实验组织

> 方法学声明：本案例是事后研究复盘；James 七连问仅为研究重建，DMAIC 是方法论映射，除非另有确证，不代表案例企业使用过这些制度。

## 执行摘要

2018年10月，哈佛商学院以Booking.com的线上实验和创新管理为主题推出案例619015。公开材料显示，Booking.com技术团队用随机对照与CUPED辅助产品决策；2017年一个挑战既有首页的方案后来成为管理学讨论的实例。同一时期，Booking Holdings集团2018年预订间夜达7.60亿，同比增长12.9%，同时对绩效营销渠道投入44.47亿美元。研究通过五力、苏格拉底式追问、James七问及事后DMAIC，考察实验学习机制的价值及边界，避免将集团增长全部归因于实验数量。

**核心判断：** 从搜索—预订流程定义CTQ，建设随机化、统计功效、护栏指标、复验和回滚机制。

## 第一部分：理解现实与明确边界

**战略命题：** 可规模化的随机实验是一种组织学习能力而非孤立技术：它可以通过缩短假设—测量—改进周期提升产品决策质量，但只有与供给、客户关系、营销效率和长期净价值管理协同才能成为可持续竞争力。

### 经历的主要节点

- **2017年｜产品实验基础进入成熟讨论：** Booking.com团队已广泛使用A/B试验；一项挑战原有首页设计的方案被提出。 [S3]
- **2018年1月22日｜发布实验统计工程实践：** Booking.com技术团队公开CUPED与A/B测试方差缩减的使用逻辑。 [S4]
- **2018年10月15日｜HBS出版Booking.com案例：** Stefan Thomke与Daniela Beyersdorfer的案例619015讨论实验如何影响数字体验与创新管理。 [S1]
- **2018年全年｜规模扩张与营销并存：** Booking Holdings集团760百万预订间夜、绩效营销约44.47亿美元；增长因素包括供给、营销及在线化。 [S2]
- **2019年3月31日｜供给规模披露：** 集团公告Booking.com上有约229万家可直接预订酒店及其他住宿设施，单位并非客房数。 [S11]
- **2019年｜HBS Working Knowledge总结实验组织：** 讨论随机对照、对结果的遵从及员工广泛参与。 [S7]
- **2020年3月｜HBR阐述实验文化：** Thomke发表Building a Culture of Experimentation，提及每年约2.5万测试及组织文化原则。 [S3]

## 第二部分：DMAIC：把实验能力变为可持续改进系统分析

**方法目的：** 事后方法映射，不是Booking.com正式六西格玛记录

### 1. Define 定义

**核心追问：** 应将哪一个现有预订体验流程作为改进对象？

**证据支持的观察：** 将搜索展示→选房→预订完成→可入住订单作为流程，以不同地区/设备/住宿品类切片，定位存在证据的用户障碍。

**反证与不确定性：** 这是基于公开资料设计的DMAIC应用样板，未发现2018年Booking.com正式DMAIC项目章程。

**建议的下一行动：** 创建项目章程：改善有效预订净价值；CTQ为可完成交易、取消率、客户满意度及酒店合作反馈。

证据索引：[S1](#s1), [S4](#s4)

### 2. Measure 测量

**核心追问：** 如何确保实验结果真实有效，而不是噪声或口径漂移？

**证据支持的观察：** 2018年技术博客解释实验的对照/处理组和CUPED方差缩减；适用于提高敏感度而非凭空创造效果。

**反证与不确定性：** 未公开可复核的原始分流日志、完整样本量、统计功效、A/A假阳性率和实验总账。

**建议的下一行动：** 定义随机化单位、流量分层、预期最小效应、试验期限，运行A/A与SRM（样本比例偏差）检查。

证据索引：[S4](#s4)

### 3. Analyze 分析

**核心追问：** 某个页面测试失败，到底是设计有误、样本不均还是用户异质性？

**证据支持的观察：** 实验平台能提供更可信的处理效应估计；仍需评估多重检验、设备差异、来源渠道、节假日与取消延迟。

**反证与不确定性：** 没有获取内部日志与统计模型，不能声称对任何具体实验完成根因统计检验。

**建议的下一行动：** 预先定义主指标及护栏，分拆渠道/设备/地区，核查暴露一致性和生命周期滞后。

证据索引：[S4](#s4), [S7](#s7), [S8](#s8)

### 4. Improve 改进

**核心追问：** 如何将数据可靠地转化为产品动作？

**证据支持的观察：** HBS案例重点是组织对证据的使用；公开技术博客显示产品团队可进行受控测试，HBR举例领导层允许挑战既有首页设计。

**反证与不确定性：** 某一网页改版的经验不能代表所有产品；业务收益未必大于成本、取消和投诉。

**建议的下一行动：** 小流量上线，设定预先决策门槛；价值为正且无明显护栏退化再灰度推广，否则复盘假设。

证据索引：[S1](#s1), [S3](#s3), [S4](#s4)

### 5. Control 控制

**核心追问：** 如何防止一次成功改版后统计质量和客户体验倒退？

**证据支持的观察：** 持续试验需要指标字典、基础设施质量、组织责任和异常检测；作者强调数据优先也需伦理与管理层授权。

**反证与不确定性：** 本研究未获得公司真实控制图、基线控制界限或六西格玛认证材料。

**建议的下一行动：** 建立实验登记簿，周审SRM/A/A/投诉/取消、月度复验效果，设回滚负责人和停止阈值。

证据索引：[S7](#s7), [S3](#s3), [S8](#s8)

## 第三部分：管理含义与决策边界

**战略建议（研究解释，不代表历史管理会议原话）：**

从搜索—预订流程定义CTQ，建设随机化、统计功效、护栏指标、复验和回滚机制。

### 证据与归因边界

- **公司自述与第三方数据须区分：** 公开采访中的口径、独立行业统计、正式披露的指标可能不同，不能直接拼接。
- **交易额、收入、利润与市场份额并不相等：** 使用前必须明确期间、分子分母与统计范围。
- **战略同时发生与严格因果归因并不相等：** 投资环境、竞争者反应和行业变化均可能影响结果。
- **成功叙事仍须允许反例：** 要审查行业淘汰者、竞争者领先区域与商户/消费者的不同体验。
- **DMAIC是方法映射：** 不得声称存在未经证实的控制图、控制限或试验结果。
- **战术有效不等于合法可持续：** 现金安全、消费者权益、商户价值和合规属于独立硬约束。

### 下一轮研究行动

- **Measure 测量：** 定义随机化单位、流量分层、预期最小效应、试验期限，运行A/A与SRM（样本比例偏差）检查。
- **Analyze 分析：** 预先定义主指标及护栏，分拆渠道/设备/地区，核查暴露一致性和生命周期滞后。
- **Improve 改进：** 小流量上线，设定预先决策门槛；价值为正且无明显护栏退化再灰度推广，否则复盘假设。
- **Control 控制：** 建立实验登记簿，周审SRM/A/A/投诉/取消、月度复验效果，设回滚负责人和停止阈值。
