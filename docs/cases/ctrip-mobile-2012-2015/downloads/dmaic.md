# DMAIC（事后映射）：携程移动互联网转型：从呼叫中心到移动交易平台

> 研究时段：2012—2015｜公司：携程 Ctrip｜行业：在线旅游 / OTA

> 方法学声明：本案例采用事后研究复盘；James 七问非携程官方固定题目，DMAIC 非经过证实的内部项目档案。

## 执行摘要

携程在2012—2015年推动由电话及PC向移动预订入口转型。公开财报证实移动交易迅速扩张、营收提升，但2014年研发及销售费用增加，归母净利润显著下降。本文将七连问及DMAIC应用于事后分析，而非声称复原当年的内部会议。

**核心判断：** 把移动战略拆成需求交付、支付成功、客户端性能、发布节奏和业务责任五组可控对象。

## 第一部分：理解现实与明确边界

**战略命题：** 竞争入口改变时，组织结构与工程交付能力必须随战略一起调整；渠道迁移成功不能等同于利润与因果归因成功。

### 经历的主要节点

- **2010｜推出移动应用：** 年报披露携程首次推出移动App [S4]
- **2013 Q2｜移动战略明确加速：** 酒店移动订单占比超过20%，机票约15% [S1]
- **2014 Q1｜移动端超过PC成为酒店预订主要平台：** 住宿预订移动交易占比超过40% [S2]
- **2014 Q4｜工程与组织转型复盘：** 16个业务团队承担自身移动产品，支付成功率一年提高约10个百分点 [S5]
- **2015｜增长与盈利归因再审查：** 2015年归母净利润含途家相关一次性会计收益，不能直接归因于移动转型 [S7]

## 第二部分：DMAIC（事后映射）分析

**方法目的：** 把战略改造成可以监测的工程体系

### 1. Define 定义

**核心追问：** 移动业务增长受到的最具体交付障碍是什么？

**证据支持的观察：** 跨业务线需求排队、支付体验薄弱和系统耦合。

**反证与不确定性：** 这是根据管理者演讲进行的项目定义重构。

**建议的下一行动：** 确定CTQ与项目边界，区分渠道迁移和交易可靠性。

证据索引：[S5](#s5)

### 2. Measure 测量

**核心追问：** 如何客观测量用户体验和研发瓶颈？

**证据支持的观察：** 按业务线追踪Online/Offline/Mobile占比、客户端加载、Payload、支付成功率和发布情况。

**反证与不确定性：** 缺少原始样本、测量系统分析和完整基线。

**建议的下一行动：** 采集客户端真实体验指标，建立基线与指标口径。

证据索引：[S5](#s5)

### 3. Analyze 分析

**核心追问：** 瓶颈来自人员数量、系统架构，还是组织职责？

**证据支持的观察：** 集中式无线开发及高度耦合限制各团队独立交付。

**反证与不确定性：** 未公开根因统计检验；保留‘管理假设’标签。

**建议的下一行动：** 用队列分析、依赖图及发布失败数据验证。

证据索引：[S5](#s5)

### 4. Improve 改进

**核心追问：** 哪些改变能突破交付约束？

**证据支持的观察：** 16个业务团队承接移动责任，拆解数据库和环境依赖，改进支付及客户端性能。

**反证与不确定性：** 不同措施的独立效应未量化；避免全部归因于单一改革。

**建议的下一行动：** 分批上线、灰度试验并记录投入与交付变化。

证据索引：[S5](#s5)

### 5. Control 控制

**核心追问：** 如何避免下一轮业务增长又被交付能力拖累？

**证据支持的观察：** 叶亚明谈到版本发布纪律、业务KPI、同行对标和实时监控。

**反证与不确定性：** 公开材料未提供项目级SPC控制图和标准控制限。

**建议的下一行动：** 建设仪表盘、触发告警及周期复盘，保留审计记录。

证据索引：[S5](#s5)

## 第三部分：管理含义与决策边界

**战略建议（研究重建，而非历史决议原文）：**

把移动战略拆成需求交付、支付成功、客户端性能、发布节奏和业务责任五组可控对象。

### 必须保留的区别

- **渠道迁移 ≠ 净增订单：** 仅凭移动交易占比不能识别真实增量与渠道替代。
- **营收增长 ≠ 单位经济改善：** 2014年研发和营销增幅高于净营业收入增幅，短期盈利承压。
- **同期变化 ≠ 管理措施的因果贡献：** 智能手机普及是重要混杂因素，未建立反事实对照。
- **管理者事后复盘 ≠ 正式DMAIC项目：** 不应虚构控制图、样本、置信区间或实验效果。
- **战术有效 ≠ 合法可持续：** 研究应包含法律、竞争影响和交易伙伴价值边界。

### 下一轮研究问题

1. 按产品线补全2012—2015年季度移动交易占比、订单量与净收入可比序列。
2. 区分App下载、月活用户、订单与复购，避免将累计下载当作活跃用户。
3. 根据同行公开财报建立对照序列，审查行业趋势与企业特定措施的差别。
4. 获取支付改进的期初期末基线、灰度分组与故障数据，才可能估计独立贡献。
